# Замер after-index

## Условия опыта

- ядер у docker: 12
- память docker: 16 770 088 960 байт (≈15,6 ГБ)
- лимиты app: 500 000 000 nanocpus (0,5 CPU), 536 870 912 байт (512 МБ) на экземпляр
- сценарий: load/mixed.ts
- профиль: load/profile.json
- данные: тот же набор, что в baseline + 150 поездок, созданных базовым прогоном
- отличие от baseline: применена миграция `db/migrations/007-history-passenger-index.sql` — индекс истории пассажира `trips_passenger_created_at_idx (passenger_id, created_at DESC)`, решение — [design/adr/010-history-index.md](../design/adr/010-history-index.md)

## Итоги прогона

| Показатель                       | baseline (до)    | after-index (после) | Цель                                       |
|----------------------------------|------------------|---------------------|--------------------------------------------|
| p95 истории                      | 106,36 мс        | **3,08 мс**         | ≤ 50 мс — выполнена, быстрее цели в 16 раз |

| Время выполнения запроса         | 61,3 мс          | **0,242 мс**        | —                                          |
| Доля ошибок                      | 0 % (0 из 952)   | **0 % (0 из 952)**  | ≤ 0,1 %                                    |
| dropped_iterations               | 0                | **0**               | 0                                          |

Распределение истории после индекса: среднее 2,31 мс, медиана 2,27 мс, минимум 1,53 мс, максимум 3,99 мс — весь диапазон далеко ниже цели. Общее p95 всех операций: 7 мс против 86,91 мс в [baseline.md](baseline.md).

### План запроса после изменения

```sql
Limit  (cost=0.43..81.17 rows=20) (actual time=0.068..0.153 rows=20 loops=1)
  ->  Index Scan using trips_passenger_created_at_idx on trips  (actual time=0.068..0.151 rows=20 loops=1)
        Index Cond: (passenger_id = 1)
        Buffers: shared hit=23 read=3
Execution Time: 0.242 ms
```

- Тип чтения: **Index Scan по trips_passenger_created_at_idx** — таблица целиком не читается.
- Прочитано строк: **20** — столько, сколько возвращает запрос (LIMIT 20); сортировки в плане больше нет, порядок задаёт сам индекс.
- Буферы: 26 страниц ≈ 208 КБ — в ~2 000 раз меньше, чем в [baseline.md](baseline.md).

## Вывод

Индекс подтвердил гипотезу из [reports/baseline.md](baseline.md): p95 истории упал со 106,36 мс до 3,08 мс, план переключился с Parallel Seq Scan на Index Scan, сортировка исчезла. Цель ≤ 50 мс выполняется с запасом. Индекс занимает 60 МБ (таблица trips — 423 МБ), на этом прогоне создание поездок шло заявленными 5/с без ошибок, деградации записи не видно. Обоснование выбора индекса и условия отката — [design/adr/010-history-index.md](../design/adr/010-history-index.md).
